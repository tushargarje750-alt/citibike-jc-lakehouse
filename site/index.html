Data engineering on Databricks

How do Jersey City and Hoboken ride Citi Bike?

This project loads every public Citi Bike trip file for Jersey City and Hoboken, adds daily weather, and cleans and tests the data in a bronze → silver → gold lakehouse on Databricks with Delta Lake and dbt. The charts below are the pipeline's gold tables.

About this demo: the numbers were exported from the project's gold tables and saved with this page. The page never contacts Databricks.

    How the pipeline works

    One Databricks job, defined in Terraform, runs these steps every Monday. GitHub Actions tests every push.

    1. Landing

      Download the files

      Lists the public Citi Bike bucket, stores each monthly zip in a Volume, and records its size, checksum and row count in a manifest table. A file is downloaded again only if it changed.

    2. Bronze

      Load raw rows

      Auto Loader appends new CSV files to a Delta table, keeping every column as text. Row counts are checked against the manifest; a mismatch fails the run.

    3. Silver

      Clean and test

      dbt types the data, applies nine named rejection rules, removes duplicate rides and joins the daily weather. Rejected rows go to a quarantine table with their reason.

    4. Gold

      Summarise

      Six small tables: daily ridership, top stations, peak hours, members vs casual riders, weather impact and trip-length statistics. Each is tested to add up to the silver trips.

    5. Serve

      Dashboard and docs

      A Databricks AI/BI dashboard reads the gold tables. The same seven queries made this page. The dbt docs show every model, column and test.
